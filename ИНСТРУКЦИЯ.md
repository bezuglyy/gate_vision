# Инструкция: интеграция «Обнаружение» (gate_vision)

Полное руководство: от установки до тонкой настройки. Версия **1.5.0**.

---

## 1. Что это

Интеграция Home Assistant, которая **определяет состояние объекта по камере** — без магнитов,
герконов и меток. Смотришь кадр камеры, выделяешь область (зону), показываешь интеграции
состояния («вот так выглядит ОТКРЫТО», «а так ЗАКРЫТО») — дальше она сама понимает, что происходит.

Типичные применения:

| Объект | Что даёт |
|---|---|
| Подъёмные/секционные ворота | «Открыто / Закрыто», уведомления, расписания, управление |
| Калитка, дверь, рольставни | «Открыто / Закрыто» |
| Лампа, подсветка, индикатор | «Включено / Выключено» |
| Любой визуальный признак в кадре | свой смысл через тип сущности |

**Ключевые возможности**

- Сущность `binary_sensor` (`device_class: garage_door`) — готова для автоматизаций, дашборда, голоса.
- **Работает днём и ночью** (камера в ИК-режиме — не проблема).
- **Обучение состояний**: показываешь состояние — интеграция запоминает (по структуре и яркости).
- **Зоны**: где искать признак, что игнорировать.
- **Реагирования**: push, уведомление в HA, TTS, скрипт, MQTT, webhook + тихие часы.
- **Расписания** запуска реле с проверкой состояния до и после.
- **Управление** (опционально): `cover` через импульсное или постоянное реле.

## 2. Установка

### Через HACS (рекомендуется)

1. HACS → **Интеграции** → ⋮ (меню справа сверху) → **Пользовательские репозитории**.
2. Добавить репозиторий: `https://github.com/bezuglyy/gate_vision`, категория **Integration**.
3. Найти «Обнаружение (gate-vision)» → **Установить**.
4. **Перезапустить Home Assistant**.

### Вручную

1. Скачать папку `custom_components/gate_vision`.
2. Положить в `<config>/custom_components/` вашего Home Assistant.
3. Перезапустить Home Assistant.

### Добавление интеграции

Настройки → **Устройства и службы** → **Добавить интеграцию** → **Обнаружение**.

В мастере укажите:

| Поле | Что писать |
|---|---|
| Название | как будет называться устройство (например «Ворота») |
| Камера Home Assistant | выбрать сущность `camera.*` (рекомендуется) |
| …или кадр напрямую | RTSP-адрес, имя потока go2rtc или готовый URL снапшота |
| Адрес go2rtc | обычно `http://127.0.0.1:1984` |
| Интервал опроса | секунды (по умолчанию 5) |

Примеры источника кадра:

```
rtsp://admin:PASS@192.168.4.200:9784/cameras/6/streaming/main   # RTSP напрямую
Ворота                                                          # имя потока в go2rtc
http://127.0.0.1:1984/api/frame.jpeg?src=...                    # готовый URL
```

> **Совет.** Добавьте поток в `go2rtc.yaml` и указывайте в интеграции просто имя — так камера
> опрашивается одним стабильным соединением.

## 3. Быстрая настройка (5 минут)

Откройте панель **«Ворота»** в боковом меню Home Assistant. Вкладка **«Настройка»**.

1. **Камера.** Раскройте «Камера и опрос» и убедитесь, что кадр живой (он виден слева).
2. **Зона.** Нарисуйте мышью прямоугольник по области, где появляется признак:
   - для ворот — по **окнам полотна** (тогда «закрыто» определяется по ним);
   - для лампы — по самой лампе.
   Тянуть — сдвинуть, за уголок — изменить размер. Стрелки на кадре двигают выбранную зону
   (с Shift — мелким шагом). Точные значения X/Y/ширина/высота — в блоке «Размер и положение».
3. **Обучение.** Приведите объект в состояние и нажмите:
   - **«Авто ЗАКРЫТО (10 замеров)»** — ворота закрыты;
   - **«Авто ОТКРЫТО (10 замеров)»** — ворота открыты.
   Автокалибровка сама соберёт 10 замеров и возьмёт медиану — точнее, чем один замер.
   **Обучите оба состояния** — днём и, если получится, ночью (можно несколько раз, берётся ближайший замер).
4. **Сущность.** Галочка **«создавать сущность»** + тип:
   - **Открыто / Закрыто** — для ворот, дверей, калиток;
   - **Включено / Выключено** — для ламп, света, любых «вкл/выкл».
   Нажмите **«Сохранить зону»**.
5. **Пресет** (необязательно) — вверху выберите «Ворота», «Дверь» или «Лампа», чтобы разом
   задать тип и имя.

Готово: в Home Assistant появится сущность, которая меняет состояние вместе с объектом.

> **Важно про расположение зоны.** Если зона нарисована **только по окнам**, рядом нет полотна —
> интеграция всё равно ищет полосу в расширенной области, но **надёжнее**, когда зона захватывает
> и окна, и немного полотна вокруг: тогда контраст виден лучше.

## 4. Зоны

| Роль | Что означает | Как используется |
|---|---|---|
| **Закрыто** | зона окна/полотна | подтверждает «закрыто» |
| **Открыто** | зона, где появляется улица/признак | подтверждает «открыто» |
| **Исключение** | помехи (тележка, столб, край кадра) | исключается из расчётов |

- **Рисование:** ЛКМ по пустому месту — новая зона; тянуть — сдвинуть; уголок — размер.
- **Точные размеры:** у выбранной зоны поля X, Y, ширина, высота (в процентах кадра).
- **Несколько зон сразу:** галочки в списке + массовые действия («применить роль», «удалить выбранные»).
- **Ctrl/Shift + клик** по зоне на кадре — добавить в выбор.
- **Автосохранение:** любая правка зоны сохраняется через долю секунды (в шапке на время правки
  видно «● не сохранено»).
- **«Зоны по умолчанию»** — вернуть проверенную геометрию.

## 5. Обучение состояний

Интеграция определяет состояние **по двум признакам**:

1. **структура** — есть ли в зоне полоса окон (у закрытого полотна есть, у открытых ворот — ровный участок);
2. **яркость** — средняя яркость зоны.

Структура важнее: она не зависит от освещения и не даёт путаницы на рассвете/закате.

| Кнопка | Что делает |
|---|---|
| **Запомнить ОТКРЫТО / ЗАКРЫТО** | один замер |
| **Авто (10 замеров)** | 10 замеров → медиана (устойчиво к выбросам) |
| **Сбросить** | очистить обучение по этой зоне |

Рекомендации:

- обучайте **оба** состояния;
- можно обучать **несколько раз** (день, вечер, ночь) — хранится до 12 замеров на состояние,
  берётся ближайший;
- если обучено только одно состояние, интеграция считает «не похоже → противоположное состояние»;
- после обучения пороги не нужны — они применяются только для необученных зон.

## 6. Сущности

| Сущность | Тип | Что показывает |
|---|---|---|
| `binary_sensor.<устройство>` | `garage_door` | **главное состояние** |
| `binary_sensor.<устройство>_<зона>` | по типу зоны | состояние отдельной области |
| `binary_sensor.<устройство>_gate_leaf_moving` | `moving` | признак движется |
| `binary_sensor.<устройство>_camera` | `connectivity` | камера отвечает |
| `sensor.<устройство>_detector_decision` | — | текстовое решение («закрыто»/«открыто») |
| `sensor.<устройство>_frame_mode` | — | режим кадра (день / ночь-ИК) |
| `sensor.<устройство>_zone_*_brightness` | — | яркость зон |
| `sensor.<устройство>_open_seconds` | `duration` | сколько открыто |
| `sensor.<устройство>_last_change` | `timestamp` | когда состояние изменилось |
| `sensor.<устройство>_last_event` | — | последнее событие |
| `cover.<устройство>` | `garage` | управление (только если включено) |

Атрибуты главного сенсора: `state`, `reason` (почему так решил), `moving`, `camera_ok`,
`changed_at`, `open_since`, `open_seconds`, `left_open`, `zones`.

## 7. Реагирования

Вкладка **«Реагирования»**. Для каждого события — включение, каналы, получатели, повтор, тихие часы.

**События:** открылись · закрылись · оставлены открытыми · движется · состояние не определяется ·
камера недоступна · камера снова доступна.

**Каналы:**

| Канал | Что нужно указать |
|---|---|
| Push (notify) | служба `notify.*` (выбирается из списка) |
| Уведомление в HA | ничего |
| Озвучка (TTS) | сущность `tts.*` + `media_player.*` (куда говорить) |
| Скрипт/служба | `script.*` / `automation.*` / `scene.*` |
| MQTT | топик |
| Webhook | URL |

Дополнительно: **повтор** (минут) и **тихие часы** (не беспокоить ночью).

**Событие на шине HA** — для своих автоматизаций:

```yaml
trigger:
  - platform: event
    event_type: gate_vision_state_changed
    event_data:
      event: opened
action:
  - service: light.turn_on
    target:
      entity_id: light.garage
```

## 8. Расписания

Вкладка **«Расписания»** — автоматизации запуска реле. Можно добавить сколько нужно.

| Поле | Значение |
|---|---|
| включено | вкл/выкл конкретной автоматизации |
| название | для журнала и уведомлений |
| время | `ЧЧ:ММ` (местное время) |
| дни | ежедневно / будни / выходные / свой набор |
| действие | **импульс** (просто нажать) · **открыть** · **закрыть** · **стоп** |
| выполнять, если состояние | любое / закрыто / открыто / движется — **проверка перед выполнением** |
| проверять результат | после импульса интеграция ждёт подтверждения по камере |

**Как работают проверки:**

- «открыть»/«закрыть» не жмут реле, если объект уже в этом состоянии;
- «стоп» срабатывает только если объект движется;
- при состоянии «неизвестно» команды не отправляются;
- если после команды состояние не подтвердилось (по умолчанию 45 с) — предупреждение в журнал
  и событие `schedule_unconfirmed`.

## 9. Управление (опционально)

Вкладка **«Управление»**. Пока галочка «Разрешить управление» снята — сущность `cover` не создаётся,
интеграция только читает состояние.

| Поле | Значение |
|---|---|
| Разрешить управление | создаёт `cover` и включает расписания |
| Способ | сущность `switch.*` или MQTT-топик реле |
| **Тип реле** | **Импульсное** — реле само даёт импульс, время нажатия не задаётся<br>**Постоянное** — интеграция держит реле заданное время и отпускает |
| Длительность нажатия | только для постоянного реле, мс |
| Ожидание подтверждения | сколько ждать подтверждения по камере, с |
| Перед закрытием проверять камеру | запрет закрытия, если камера недоступна |

**Защита:** команды не отправляются при неизвестном состоянии; после импульса ждём подтверждения;
всё пишется в журнал.

## 10. Диагностика и журнал

- **Шапка панели**: состояние, замеры обученных зон, признак «движется», «устаревшее»,
  «камера недоступна».
- **Вкладка «Журнал»**: последние события с причинами.
- **Кнопка «Проверить сейчас»** — принудительный опрос камеры.
- **Сенсоры диагностики**: режим кадра, яркости зон, решение детектора.

### HTTP API (для скриптов, нужна авторизация HA)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/gate_vision/frame?fresh=1` | последний кадр (JPEG) |
| GET | `/api/gate_vision/state` | состояние + анализ + настройки + журнал |
| GET | `/api/gate_vision/settings` | настройки |
| POST | `/api/gate_vision/settings` | изменить зоны/пороги/реагирования/расписания/управление |
| POST | `/api/gate_vision/learn` | обучение: `{zone_id, state, count}` или `{zone_id, action:"reset"}` |
| POST | `/api/gate_vision/test` | принудительная проверка кадра |
| GET | `/api/gate_vision/events?limit=50` | журнал событий |

## 11. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Состояние «неизвестно» | кадр тёмный/нечитаемый; проверьте камеру и освещение |
| Постоянно «открыто» при закрытом объекте | зона не обучена или обучена при другом освещении — обучите оба состояния кнопкой «Авто» |
| Ложное «движется» | резкая смена освещения; поднимите порог «Порог движения» в «Дополнительно» |
| Положение зоны не сохраняется | обновите страницу панели (Ctrl+F5) — в старых версиях живое обновление затирало правки |
| Сущность `cover` не появилась | не включена галочка «Разрешить управление» |
| Расписание не сработало | проверьте условие «выполнять, если состояние» и журнал (там будет причина пропуска) |
| Камера недоступна | проверьте поток в go2rtc; интеграция делает 3 попытки на кадр |

## 12. Обновление

- **HACS**: появится уведомление о новой версии → «Обновить» → перезапуск Home Assistant.
- **Вручную**: заменить папку `custom_components/gate_vision` → перезапуск.
- После обновления панели откройте её и нажмите **Ctrl+F5** (сбросить кэш браузера).

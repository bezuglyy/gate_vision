# Проект «Ворота» (gate-vision)

**Создан:** 15.09.2026
**Статус:** ⏳ ждём установку метки (красный квадрат 20×20 см — Алик ещё не сделал). На ARM работает **сторож** (`tools/watch_marker.py`, cron 5 мин) — сам напишет, когда метка появится (16.09.2026).
**Задача:** определять состояние подъёмных ворот (открыто / закрыто / движется) по камере и управлять ими из Home Assistant (База).

---

## 1. Что делаем

- Ворота с **одним импульсным реле**: каждое нажатие = следующее действие.
- Есть **камера на воротах**; на полотне внизу предполагается **красный квадрат 20×20 см**.
- Нужно: система понимает состояние ворот по картинке и управляет ими (open / stop / close) из HA.

## 2. Логика ворот (подтверждена пользователем 15.09.2026)

Один импульс = следующее действие в цикле:

| Состояние             | Импульс → результат |
| --------------------- | ------------------- |
| Закрыто               | → Открывается       |
| Открывается           | → Стоп              |
| Стоп (после открытия) | → Закрывается       |
| Закрывается           | → Стоп              |
| Стоп (после закрытия) | → Открывается       |

**Ключевое:** направление следующего пуска **противоположно** последнему движению → аддон обязан помнить последнее направление.

### Маппинг на команды `cover`
- **OPEN:** закрыто → 1 импульс; закрывается → 2 (стоп + открыть); открыто/открывается → нет.
- **CLOSE:** открыто → 1 импульс; открывается → 2 (стоп + закрыть); закрыто/закрывается → нет.
- **STOP:** движется → 1 импульс; покой → нет.

## 4a. Сторож появления метки (16.09.2026)

Пока красный квадрат не наклеен, на **ARM** работает сторож, который каждые 5 минут проверяет кадр камеры ворот и **сам напишет**, когда метка появится.

| Параметр | Значение |
|---|---|
| Скрипт | `/opt/harness/projects/vorota/tools/watch_marker.py` |
| Запуск | cron (root, ARM): `*/5 * * * *` |
| Источник кадра | go2rtc База `:1984`, ad-hoc RTSP **ch6** NVR 192.168.4.200:9784 |
| Лог | `/var/log/vorota-marker.log` |
| Состояние | `state/marker.json` |
| Кадры детекции | `frames/detected/marker-<stamp>.jpg` |
| Тесты детектора | `tests/test_marker_{60,150,300}.jpg` (синтетический красный квадрат) |
| Уведомление | e-mail `bezuglyy@postcorp.ru` (SMTP 192.168.10.14:587) + HA push `notify.mobile_app_iphone_administrator` |
| Повтор | напоминание раз в 6 ч, пока метка на месте |

**Критерии детекции:** насыщенность ≥ 0.55, яркость ≥ 0.35, r > g·1.15 и r > b·1.15, компонента квадратная (стороны 0.55–1.8), заполнение ≥ 0.5, сторона 20–640 px. Плитка на полу (sat ≈ 0.40) порог не проходит. Ночью/в ИК кадр ч/б (mean_sat < 0.02) — красный не читается, сторож это фиксирует и не считает детекцией.

Проверки 16.09.2026: кадр с камеры получен (2304×1296, цвет), детектор найденного не дал (метки нет); синтетические квадраты 60/150/300 px — детектируются; канал e-mail и HA push — рабочие.

## 4b. Решение 16.09.2026: без метки — следим за полотном

По предложению пользователя красный квадрат **не клеим** (Алик не нужен): состояние ворот определяем по самому полотну.

| Признак | Когда работает | Замеры |
|---|---|---|
| **Нижняя кромка полотна** | основой, все положения | открыто: кромка y≈20–65 (градиент **20–38** — очень сильный); закрыто: кромка у пола (y≈392 в 720p), но слабая (градиент <1 — тёмное на тёмном) |
| **Окна полотна** (2 ряда по 4) | закрыто / чуть открыто | пересвет с улицы, градиент до 20 на границах y≈107/167/239 |
| **Пересвет улицы под кромкой** | открыто (день) | доля пересвеченных пикселей проёма 0.49 (открыто) против 0.19 (закрыто) |

**Плюс:** не зависит от цвета → **работает в ИК/ч-б ночью**. **Минус:** когда ворота закрыты, нижняя кромка визуально «тонет» (тёмное на тёмном) → нужна калибровка по реальным сериям движения; и нужен разбор ночного режима.

### Что запущено (read-only, реле не трогает)

| Компонент | Где | Что делает |
|---|---|---|
| `tools/gate_recorder.py` | ARM, systemd **`vorota-recorder.service`** (с 16.09 14:24) | опрос камеры каждые 5 с; при изменении кадра — серия кадров 1/с (движение полотна); ключевой кадр раз в 10 мин; ряд `state/recorder.jsonl`; кадры `frames/collect/` |

**Что даёт:** как только ворота откроют/закроют — серия запишется автоматически, и детектор можно откалибровать по факту (день/ночь, все положения).

### v1.2.0 — исправление ложного «открыто» + удобства панели (17.09.2026)

**Исправление в детекторе:**
- **Окна полотна — главный признак «закрыто»**: ищется полоса, зажатая полотном сверху и снизу, **обеих полярностей** (днём яркая, ночью/ИК тёмная).
- Полосы, разорванные перемычкой между рядами окон, **склеиваются** (`merge_gap = 8 % линии пола`).
- Допустимые размеры полосы считаются от **линии пола**, а не от зоны поиска (иначе большая зона ломала проверку).
- Новый порог **`dark_band`** («Окна ночью», по умолчанию 70) — есть ползунок в панели.

**Проверено: 5/5 эталонных кадров** — день закрыто, ночь закрыто, **рассвет закрыто**, день открыто, день приоткрыто. На живом кадре 07:33: `closed`, причина «окна полотна видны (яркая полоса y 204–433)».

**Панель «Ворота» (по запросу):**
- **Точные размеры зон** — у выбранной зоны поля X, Y, ширина, высота в процентах (в списке показывается `27.0×27.0 %`).
- **Стрелки** на кадре двигают выбранную зону (Shift — мелкий шаг).
- **Выбор одной или нескольких зон** галочками + массовые действия: применить роль, удалить выбранные, снять выбор.
- Кнопка **«◀ В меню»** — возврат в меню Home Assistant.
- Выбор устройств из списков (v1.1.0): камера `camera.*`, `notify.*`, `tts.*`, `media_player.*`, `script.*`, реле `switch.*`.
